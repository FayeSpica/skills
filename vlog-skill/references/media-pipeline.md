# 媒体技术与验证

用于脚本化剪辑、混音、导出和排查声画问题。以下不变量来自实际剪辑故障；帧率、采样率、编码器、增益和阈值按当前素材选择。

## 时间线的两个时基

视频用整数帧，音频用整数采样。若帧率为 `p/q`、采样率为 `sr`，累计帧边界 `F` 对应：

```text
time(F) = F × q / p
sample(F) = round(F × sr × q / p)
shot_samples = sample(end_frame) - sample(start_frame)
```

所有起点由累计边界派生，避免逐镜独立四舍五入累积误差。整数计算或有理数比重复浮点加法稳定；29.97 等分数帧率尤其需要累计边界取差。源入点与输出帧边界分别保留。

时间线至少记录：

| 对象 | 字段 |
|---|---|
| 镜头 | source、source_in、source_out、start_frame、frame_count、chapter、reason、original_audio_gain |
| 音乐 | source/version、source_in、timeline_start、duration、gain、fade_in/out、节奏证据 |
| 事件 | type、frame、duration_frames、asset、gain/opacity、关联照片或章节 |
| 采用记录 | 用户候选 ID、原素材与时间点、采用镜头或合并对象、原因 |

验证源入出点没有超出真实时长、镜头和章节连续、音乐窗口可用。时长参数在 FFmpeg 中使用 `0.5` 等完整数字；本项目曾因 `.5` 解析失败中断抽帧。

## 卡点与版本替换

节奏检测先给候选：起音强度、谱通量、RMS 上升沿和自相关周期可辅助定位，不能单独证明乐句边界。对照实际音频，选择整组或半组切镜，并保留动作完成的例外理由。帧量化后复查邻近帧的入点。

音乐源时间与成片时间的基本关系：

```text
timeline_time = source_time - source_in + timeline_start
```

改为器乐版等其他版本时，至少用前后多个有辨识度窗口核对偏移和速度。只有稳定偏移才适合沿用旧网格；版本长度、前奏或速度变化时重建。不能凭同名认为同步。

视觉参考、可用配乐、原片人声和相机音效分别登记，避免把参考 OP 的旁白混入正式音轨。快门实录保留原文件与裁剪窗口；有多个同名版本时可记录哈希。

## 避免 AAC 累计漂移

逐段 AAC 的编码延迟、补齐和重叠 PTS 会让拼接后的解码时长偏离画面。不能把“拼接分段 AAC 后得到的音轨”未经验证就作为混音时钟。

可靠路径：

1. 每镜直接解码原音轨到统一采样率、声道和 PCM 格式，处理该镜需要的增益、滤波和淡入淡出。
2. 精确裁剪或补静音到由帧边界计算的样本数。静音镜头也保留相同长度。
3. 拼成连续 PCM 时间线，再按全局样本位置加入 BGM 和效果音；主混音最后编码一次 AAC。
4. 混音后检查真实样本总数。若短缺或超长，先定位漂移、滤镜延迟或尾包问题，再决定处理方式。

少量尾端静音补齐只能修复已验证的尾差；不能修复中段逐渐提前。先核对前中后的事件位置，再确认末尾已经衰减且补齐不会截掉尾音。记录预期、实际、差额和原因；字节数由实际声道数和采样位宽计算，不硬编码“双声道 PCM16 每帧 4 字节”。

## 画面只做必要的一次有损编码

- 原视频或原照片 → 比例/色彩处理 → 所有文字、照片框、闪白、进度条 → 分段正式编码。合成层和滤镜的像素格式也需检查，避免中途悄悄降为 8 位。
- 分段参数兼容时，最终拼接与封装复制视频流（如 `-c:v copy`）。新增图层回源重渲染受影响镜头，而非拿最终成片再压一次。
- 缓存键应包含源文件身份、裁剪窗口、长度、图层、色彩、尺寸、帧率和编码设置；“缓存文件存在”不等于可以复用。
- 代理视频和候选 JPG 用于浏览，正式输出回原 MP4 / HIF / 照片。照片解码格式本身会限制位深；10 位输出容器不意味着 8 位 RGB 中间图恢复了精度。
- 探测色彩标记再选择流程。HDR、Log、SDR 不混用假定 LUT；缩放保持原比例。为竖画面决定留边或明确裁切，不能静默拉伸。
- 树叶、水纹、远景等复杂纹理用于原片/新编码/旧版比较；编码小样衡量质量、时间和文件大小。硬件码率目标不等于实际码率；输出 4K 不等于所有来源原生 4K。

## 图层与照片事件

报幕开始、结束和淡入淡出以全局帧边界定义；跨镜头继续同一动画进度。局部滤镜时间须由全局时间换算，检查边界前一帧、首帧和后一帧，防止 25.00 秒写在配置里却晚一帧出现。

快门与照片首帧共同定义事件。闪白只短暂覆盖该照片画面；强度和持续帧数按帧率与参考观感调整。静止性核对避开闪白和编码初始瞬态，并区分轻微压缩像素变化与实际推拉、漂移。

## 验证最终文件

报告绑定实际输出路径、大小和修改时间；必要时增加哈希。成片重封装或改版后，确认复用的报告仍对应相同内容与修改范围。

| 层面 | 要检查的对象 | 结论边界 |
|---|---|---|
| 素材与计划 | 文件存在、源范围、排除项、选片采用、尾声重复 | 证明选用了什么，不能证明镜头好看 |
| 容器与完整解码 | 尺寸、帧率、位深、色彩、声道、帧数、时间戳、时长、章节、解码错误 | 证明可解码与结构一致，不能证明叙事或音乐节奏 |
| 最终音频 | 每首配乐前后至少两个有辨识度窗口与原音源比较，全部快门事件逐个核对，测响度/真峰值/尾音 | 波形相关只证明所测窗口；阈值须随信号质量调整 |
| 边界与画质 | 报幕、切黑/恢复、照片闪白、转场逐帧；原片与输出细节对比 | 代表帧与样本不能替代全片观看 |
| 连续视听 | 动作完成、音乐乐句、人声、接缝、节奏密度与尾声收束 | 未实际试听时不能宣称已听过或主观顺畅 |

原声掩盖配乐时，可辅助估计并移除已知原声的线性分量以复核相关；同时保存原始结果，不将其称为完整人声分离。相关结果不可靠时增加可辨识窗口，避免单纯放宽阈值让检查通过。

使用工具测最终 AAC 的实际响度和真峰值；规范化目标不等于最终测值。播放器的声画起点与尾音也要核对。音乐错位修复以后，只重验受影响项和最终文件的必要完整性，避免无理由反复重渲染。

## 已验证案例的边界

新疆项目 V11 使用 25fps、48kHz、4K HEVC Main10、VideoToolbox 目标 50Mbps，属于该设备和素材的方案。音视频总长 285.24 秒；最终配乐十个窗口最大误差 0.1875ms、八次快门在 16kHz 分析网格上偏差 0ms，响度 −17.6LUFS、真峰值 −1.8dBFS。这些是一次输出的实测结果，不是未来项目必须达到的常量。

当时并未完成全片连续主观试听；完整解码、波形抽样与代表帧目视检查分别记录。工程路径和更多案例限定见 [新疆案例](xinjiang-case.md)。
